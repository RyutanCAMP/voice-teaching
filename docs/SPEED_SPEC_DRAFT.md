## 3. 調べた結果から言えること（このアプリへの影響）
- **単位が分からないまま数値を変えると、表示の mm/s と実際が約6倍ずれる可能性がある**（F2・F3・F7）。単位が確定するまで速度の変更を再開しない理由になります。
- 実際の速度は、JBI の V= だけでは決まりません。**オーバーライド（F16）、速度制限運転（F18）、協働運転の速度制限（F21）**などで、書いた値より遅くなることがあります。このアプリの画面では「この値で動く」とは言えず、「ジョブに書く値」として出すのが正確です。
- VR=・VE=・VMAX=・変数・速度の省略（F8〜F14）は、V= の数値を変えても意図した速さにならない、または別の値が使われる形です。どれも**止める**対象にします。
- オーバーライドの「速度データ修正：ON」やペンダントの一括変更（F16・F17）で、ジョブの速度が現場で書き換わることがあります。仕様6章の「正規化した中身のハッシュが一致しなければ変更させない」で拾える見込みですが、読み戻しで実際にどの行が変わるかは要確認です（4章 C12）。

## 5. 仕様案（案です。本人の承認待ち）

### 5-1. 速度の変更を再開する条件（すべて満たしたときだけ）
1. C1・C2（できれば C3・C4）で **JBI の V= の単位が確定**し、本人が `docs/JBI_FORMAT_NOTES.md` の「直線速度 V= の単位」を「確認済み」に書き換えることを承認した
2. C6 で協働運転の速度制限の設定値を本人が確かめ、専門家の枠（速度の上限）に反映した
3. C14（PL=0）が決まった
4. 5-3 の検査について、**受入テストを先に書き**、テストが通った
5. 本人がこの文書を承認した

それまでは、速度の変更の依頼はすべて「現在は速度の変更を受け付けていません」と理由を返して止めます（今の禁止を続ける）。

### 5-2. 扱う形式
- 変えてよいのは、**`MOVL 位置 V=数値` だけの行**（今の許可リスト `_EDITABLE_MOVL` と同じ考え）
- 止めるもの（行）：
  - V= が変数（`V=I000`、`V=D001`、`V=B[1]` など）
  - **VR=・VE=・VMAX=** が付いた行、または V= の代わりにこれらが書かれた行
  - 速度の札が無い MOVL（SPEED 命令や前のステップの速度が使われる形。F13・F14）
  - PL・CR（PL=0 の扱いは C14 待ち）、ACC=・DEC=、NWAIT、UNTIL、+MOVx（同時移動）、その他の知らない語
  - MOVJ（VJ= の % は対象外）・MOVC・MOVS・IMOV・SMOVx
- 止めるもの（ジョブ全体の速度の変更）：
  - ジョブに **SPEED 命令がある**とき（どの移動に効くかを行の並びだけで決められないため。本人が不要と判断すれば外す）
  - 今の「ジョブ全体を止める」もの（`docs/JBI_FORMAT_NOTES.md`）
- **数値の書き方の確認**：単位が確定したら、その単位の書き方（例：mm/s なら小数1桁、cm/min なら整数。F7 の例の形。実際の書き方は C2・C12 で確定）と合わない V= の行は止める

### 5-3. 検査の内容（プログラムが計算・判定する）
| 検査 | 内容（案） |
|---|---|
| 単位 | 枠の設定に「JBI の V= の単位」を専門家が書く（C1〜C4 で確定した値）。書いていない枠では速度を変えさせない |
| 下限・上限 | 新しい速度が、専門家の枠の**下限以上・上限以下**（mm/s で比べる）。さらに 0 より大きく、資料の範囲（0.1〜1500.0 mm/s、C10 で HC20 の値に置き換え）の中 |
| 上限と協働運転の制限 | 枠の速度の上限が、専門家が書いた「協働運転の速度制限の設定値（C6）」を超える枠は受け付けない（案。本人が決める） |
| 1回の変化率 | \|新しい速度 ÷ 今の速度 − 1\| が、枠の「1回の変更量（%）」以下 |
| 累積 | 基準（専門家が枠を保存したときの元のジョブ）の速度に対して、新しい速度が枠の範囲（元の速度に対する %、仕様 v2.1 5-2）の中。基準は正規化した中身のハッシュで引き継ぐ（仕様6章） |
| 丸め | 単位の刻み（mm/s なら 0.1、cm/min なら 1）に丸めたあとの**実際の値で、上のすべてを検査し直す**。超えたら丸めを調整せず止める。丸めて値が変わらない・0 になるときも止める |
| 前後の命令 | 直前・直後の移動命令に PL>0・CR がない（PL=0 は C14 次第）。**直前の移動命令が無い**（ジョブの最初の移動）ときは、区間の始まりがジョブから分からないので止める（今の実装は止めていない。案） |
| 流れの命令 | JUMP・CALL・RET があるときは、前後は行の並びからの推定であることを注意として出す（今と同じ） |
| 割合の意味 | 話し言葉の「◯%上げて」は**今の速度に対する割合**（仕様 v2.1 5-2）。Claude は数値を書かず、プログラムが計算する。断られた発話の中で Claude は量を変えて出し直さない |

### 5-4. 表示
- 速度は **mm/s** で出す（仕様4章）。JBI の単位が mm/s 以外なら、プログラムが換算した mm/s と、ジョブに書く元の値・単位を並べて出す
- 速度の近くに常に次の注記を出す：
  - 「協働運転の速度制限で、実際の速度が頭打ちになることがあります」（仕様4章）
  - 「再生時の速度オーバーライド、低速スタート、速度制限運転などでも、実際の速度はジョブに書いた値と違うことがあります」
- 「この速度で動きます」とは書かず、「ジョブに書く速度」と書く
- サイクルタイムの見込みは出さない（実際の速度が上の理由で決まらないため）。比べるのは実機で測った時間だけ
- 「安全」「当たる」などの断定の言葉は、画面・文章・枠のメモのどれにも使わない

## 6. 今の実装との差（参考。コードは変えていない）
- 今の `plan_speed` は、MOVL・数値の V=・PL/CR・前後の PL/CR・正の有限数・丸めを確かめている。枠（下限・上限・1回の変化率・累積）と単位の検査はまだ無い
- 今の実装は **SPEED 命令**があるジョブ、**直前の移動命令が無い**行でも速度を変えられる（5-2・5-3 の案では止める）
- VR=・VE=・VMAX=・ACC=・DEC=・変数の V= は、許可リスト（`MOVL 位置 V=数値` 以外は止める）で今も止まる見込み。受入テストで確かめる

**検査を通ったことは、実機での動きの保証ではありません。** 変更後の動きは、人が確かめてから承認します。
