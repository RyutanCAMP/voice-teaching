## 3. 開発優先度と機能範囲

優先度：**(1) 出力・承認・方向の安全整合性 → (2) 主要デモの安定動作 → (3) 自然言語理解の質 → (4) UI磨き込み → (5) 追加機能**。時間切れなら新機能より提出を優先。

### シクロ：自然言語とAPI活用
- 狙いは**「人がAIに合わせるのではなく、AIが自然な言葉を理解する」**。Claudeを意味理解の中心に据え、**曖昧さを推測で埋めない**。不足情報は質問。
- 人の発話から意図・位置・方向・量を抽出し、Python側で数値・根拠文字列・単位・対象・方向・安全制約・出力を**独立に検証**する。Claudeの自信やJSON出力だけで動作候補を確定しない。
- 表現の揺れ、cm/mm、上下左右の確認、会話継続、訂正・否定、説明の自然さを改善。位置／JOB／座標系が変われば方向確認状態を適切に破棄。
- **最新の意思表示と古い候補の誤結合を防ぐ**（F-2/Q-3）。「だめ」「ノー」は承認を無効化。「大丈夫？」は質問であって承認ではない。
- 回数変更は提出版で**2回→3回のみ**。能力の過大表現・未実装機能のデモは禁止。
- **API呼び出しの利用管理**：`decide`／`understand`／説明系を含む全経路の呼び出し・予算管理の抜けを点検。Maxプラン利用枠とAPI従量課金は別物。予算・失敗時・並列実行の扱いを記録。無制限の実API連続評価は避ける。

### クローク：本番用総合QA
- **撮影版ではなく最新RCの実挙動**を優先。まずF-2/Q-3と、以前指摘のXC-01（対象切替と向き状態）、XC-02（否定でも未承認候補が承認可能）、XC-03（ためらい語）、R10、N-1/N-2、SIM再読み込みの累積・JOB異常値などを再テスト。
- 挙動を「合格」「修正確認待ち」「既知制限」「未確認」で厳密に分ける。深刻なバグは正午を待たずにシクロ・チャッピーへ通知。
- 誤候補0・古い承認を使った出力0・誤った対象位置0など、数値付きで再現試験。実機での動作試験・安全認証とは区別。

### クーちゃん：UI・UXの完成度
- **初めての人でも迷わない操作フロー**：JOB読込→3Dと位置選択→音声／文字指示→理解・聞き返し→変更前後の数値・3D差分→明示承認→SIM出力。
- 重要なボタンと確認・警告を明瞭に。3Dは大きく、必要な座標・方向・量は読みやすく。不要な専門用語、長い文章、開発用バッジ、重複案内を整理。
- レイアウトは1920×1080、1440×900、1280×720を最低確認。候補パネルが会話を覆わない、エラーを誤解させない、空送信を許さない、視線の流れがよいこと。
- **Appleそのものの意匠をコピーするのではなく**、シンプルさと使いやすさを品質目標とする。原則まず精査と比較画像、必要なら限定CSS/UI変更を別ブランチに。
- 安全の盾アイコン、合成JOBのSIM専用表示、20mm等の制限・差分と承認は視認性を維持。UI上の承認状態とサーバーの状態を一致させる。

## 4. 不変の安全／データ境界

- **実機への接続・動作指示・転送・送信は行わない。** デモは合成JOB、SIMテキスト出力のみ。実機撮影映像は**Voice Teachingが実機を直接動かした証拠ではない**。動画・READMEでも誤認させない。
- 既存の1指示20mm上限・累積判定・対象位置／座標系制約・構造検査・差分・人間の明示承認を**緩和しない**。上限を満たしてもロボットの実機安全性が保証されるわけではない。
- 方向・座標・対象・数値が曖昧なら候補に進めず質問／停止。矛盾する複数値を勝手に選ばない。
- JOBの再読込・位置切替・候補変更・取り消し・保留・承認後の言い直しで、古い候補・承認・方向確認状態が誤って再利用されないこと。
- 未承認の候補は出力しない。説明・問いかけ・「はい」等で承認を代用しない。エラー時は安全側に停止。
- 実機JOB・機密座標はローカルの保護環境に留め、公開GitHubやAPI入力へ無断で含めない。
