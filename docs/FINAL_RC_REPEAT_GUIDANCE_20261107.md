# Voice Teaching v1.0 — 繰り返し範囲の案内改善・全担当指示
**2026-11-07／唐川の本番アプリ実操作で発見。実装前の追加要件。**

> 読む順：本書 → [最終スプリント計画](./FINAL_SPRINT_PLAN_20261107.md) → [承認1回化と保存改善の追加仕様](./FINAL_RC_CHANGE_REQUEST_20261107_APPROVAL_SAVE.md)。既存の先行指示を無効にせず、今日本番アプリ・動画を仕上げることが最優先。担当エージェントへの自動送信・自動実行を意味しない。

## 1. 発見した問題とユーザー要望

画面でユーザーが「**C1 C4を2回繰り返したい**」と自然な言葉で指示したところ、現行アプリは「**C00001からC00003の作業を2回から3回にして**と言ってください」と定型文を要求し、利用者には**どこが繰り返し可能なのか分からない**状態だった。

**ユーザーの要望：**「繰り返し・2回・3回」のような回数を表す言葉を認識したら、アプリが**このJOBで変更できる範囲を分かりやすく表示・案内**してほしい。人がアプリの定型文を覚えるのではなく、アプリがユーザーに可能な操作を教える。

## 2. 受け入れ仕様（ユーザーの希望を最優先）

1. 繰り返し・反復・回数・「2回」「3回」など、回数変更の**意図を検出**したとき、現在ロード済みのJOBの実際の対応範囲を調べる。単語「回」だけで危険な操作を自動確定しない。
2. **対応範囲をC番号で表示**（例：`C00001〜C00003`）。開始点と終了点を明示し、できれば3Dでも区間・対応位置を強調表示する。未対応のJOBなら「このJOBは繰り返し変更に対応していません」と案内。**JOBを読まずに固定範囲を作り話しない**。
3. ユーザー例の「C1〜C4」はアプリの対応範囲「C00001〜C00003」と一致しない可能性がある。**黙ってC1〜C3へ置き換えて変更しない**。違いを説明し、ユーザーに範囲を確認／選択してもらう。全角・短縮表記のC1/C00001は表示上補助的に正規化しても、対象同定を曖昧にしない。
4. **本番版で許される実変更は、既存仕様の2回→3回かつ実装済みの対応範囲のみ**。2回に「したい」という曖昧な発話を勝手に2→3へ解釈してはいけない。「2回にしたい」「2回繰り返したい」なら、現状2回と希望回数の意味を聞き返す。既存の安全ガードと承認状態の検査を維持。
5. 範囲案内は**提案・選択支援**であり、範囲の表示・クリック・音声応答だけでJOB編集や承認をしない。確認された意図→対応可否→差分表示→**人間の明示承認1回**→SIMファイル出力（別途承認1回化の最新要件に準拠）。
6. 必要な画面表現：利用者「ここを繰り返したい」→「繰り返しですね。このJOBで変更できるのはC00001〜C00003です。現在2回から3回への変更に対応しています。範囲と回数を確認してください」。**わかりやすい日本語**、専門用語は必要最小限。C00004まで要求された場合は非対応範囲を明示。
7. 複数の繰り返し候補に対応する一般化は今は**将来案**。今回は判別できる既存1範囲の表示に限定し、未知範囲を推測しない。3D連携が重い場合は**C番号の案内＋選択UIを先行**して、本日中の安定版・動画を確保。
8. 空JOB、異常JOB、回数意図が曖昧、別JOB読込、位置切替、否定・取消、連打、古い承認状態、API誤解釈時にも不正な編集・出力をしない。実機接続・実機JOB転送は禁止、合成SIMのみ。原本JOBは不変。
9. 承認1回化・日時ファイル名・保存先選択の先行追加要件との**競合を避ける**。ファイルを同時編集しない。今日の動画・翌11/8の提出（従来の管理期限14:00 JST）を妨げる追加開発は見送る。
