# ロボットのバックアップ解析：設計メモ（ハッカソン後の拡張候補・実装しない）

書いた人：シクロ（会社の PC）。2026-11-03。唐川さんの指示⑥（本線を止めずに、設計メモとして残す）。
状態：**メモだけ。実装・本線への組み込みはハッカソンの後に判断する**。

## 1. したいこと
コントローラーのバックアップ（ZIP）をアプリに入れるだけで、次を自動で表示する。
- ロボットの型式とスペック（軸数・可搬重量・動作範囲などの表示用の情報）
- 使っているツール（ツール番号とツールの設定）
- ユーザーフレーム
- JOB の一覧（JBI）

型式が特定できないときは、勝手に決めず、**機種の一覧から人が選ぶ**。

## 2. 分かっていること（唐川さんの実機バックアップから。中身はリポジトリに入れない）
- 型式、使っているツール番号、ツールの設定ファイル（TOOL.CND）、ユーザーフレームの設定ファイル（UFRAME.CND）、JOB（JBI）が取り出せた
- 実機のバックアップは会社のデータなので、このリポジトリには入れない（CLAUDE.md）。テストには、構造をまねた架空のバックアップ（samples/dummy に新しく作る）だけを使う

## 3. 流れ（案）
```
ZIP を入れる
 ① ZIP の安全な展開：サイズ・ファイル数・パス（../ や絶対パス）・圧縮率を検査。メモリ上だけで読み、ディスクに展開しない
 ② ファイルの種類を見分ける：*.JBI、TOOL.CND、UFRAME.CND、型式が書かれたファイル（どれに書かれているかは実機で確認する）
 ③ 読むだけで解析：今の jbi.py（読むだけ）と、新しい cnd の読み取り（読むだけ）。分からない形式は「読めませんでした」で止める
 ④ 型式：見つかれば表示。見つからない・機種の一覧に無い → 一覧から人が選ぶ（推測しない）
 ⑤ 表示：型式・スペック（一覧の値）・ツール・ユーザーフレーム・JOB の一覧。JOB を選ぶと今の 4ステップの画面へ
```

## 4. 安全と線引き（今の決まりのまま）
- 読むだけ。バックアップを書き換えない。ロボットへ送らない・起動しない
- スペックの値（動作範囲など）は**表示用の参考**。安全の判断には使わない（「動作範囲の中なので当たりません」などは言わない）
- TOOL・UFRAME の値を JOB の変更に使うのは、FRAME と実機の確認のあと（座標の意味が変わるため。今の JOB の変更は ROBOT 座標・TOOL の一致だけを見る）
- 実機のファイル名・中身・顧客名は、ログや画面のスクリーンショットをリポジトリに入れない
- ZIP の扱い（zip bomb・パストラバーサル）は Safety レビューの対象にする

## 5. 決めること・確かめること（ハッカソンの後）
1. 型式がバックアップのどのファイルのどこに書かれているか（実機で確認。推測で決めない）
2. 機種の一覧（データベース）の持ち方：公開資料から作る範囲、版の管理
3. TOOL.CND・UFRAME.CND の形式（メーカーの資料と実機で確認）
4. マルチメーカー対応の入口（メーカーごとに「バックアップを読む部品」を分ける）

## 6. テストの計画（実装するときに先に書く）
- 架空のバックアップ ZIP（正しい形、型式なし、壊れた ZIP、../ を含む、巨大な展開サイズ、ファイル数の上限越え、Shift_JIS のファイル名）
- 型式が無いときは一覧から選ぶ画面になり、推測で埋めない
- 読んだあと、元の ZIP のバイト列が変わっていない
