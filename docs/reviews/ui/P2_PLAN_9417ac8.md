## 2. 改善案（優先の3つ）
### 2-1. 軸の文字の欠けと、前後の点が見えない（V1・U8）
- 原因
  - `view3d.js` 80〜88行目：`data.focus`（区間の3点）があると、その3点を中心に `span` を縮める（設計どおり。コメントに「区間の外の点は図の外に出ることがある」）
  - 軸は、点の重心から一番遠い床の角から描く（395〜423行目）。文字の置き場所は点と点の名前を避けて探すが、**枠（W・H）の内側かどうかは見ていない**
- 案A（推奨・見た目だけ）：`app.js` 1332行目の `focus` に、区間の前後の位置も入れる（`rc.repeat.positions` の前後。動きの並びのカードに出している「C00000（区間の前）」「C00004（区間の後）」と同じもの）。区間の3点は今より少し小さくなるが、くり返しの入口と出口が映る
- 案B（案A と一緒に）：`view3d.js` の軸の文字の置き場所の探し方に、「枠の内側（左右上下 8px の余白、左下の『格子 ○mm』『ドラッグで回す…』の2行は避ける）」の条件を足す。どこにも置けないときは、枠の内側に寄せた位置に置く
- 案C（撮影だけの対策）：撮影の前に 3D を手で少し引いてから撮る。ただし、候補を作るたびに視点が戻る
- 合格の線：S3・S4r・S4（位置の候補）で、両方の画面サイズで、軸の文字3つと区間の前後の点が 3D の枠の中に入る（クロクラウドのレビュー用の道具 `fig_s4r.js` で測る。リポジトリには入れていない。e2e に同じ測り方を足してもよい）。区間の3点の名前どうしが重ならない（e2e の今のチェック）

### 2-2. 操作ボタンの文言（U11）
- 直す所（ボタンの文字「送る」に合わせる。ボタンは変えない）
  - `app.js` 424行目：`文を確かめて「次へ」` → `文を確かめて「送る」`
  - `app.js` 441行目：`動かし方を書いて「次へ」` → `動かし方を書いて「送る」`
  - `app.js` 488行目 `HERO_REPLACES` の同じ文も、同時に直す（入れ忘れると初期の見出しの入れ替えが効かなくなる）
  - `index.html` 38行目：`話した文は欄に入るだけ。『次へ』で送ります` → `話した文は欄に入るだけ。『送る』で送ります`
- テストの期待値も直す：`tests/test_ux_polish.py` 72行目、`tools/e2e_browser.py` 2755行目の文
- 合格の線：画面の文に「次へ」が残っていない（`grep -rn "次へ" voice_teaching/web/static` が0件）

### 2-3. 範囲の説明（U6）
- **サーバーの文（`repeat_count.py` の `range_message`）は変えない**（動作ロジックの側。P1-C と分ける）
- 案A（推奨・並べ替えだけ）：`app.js` 682〜691行目の `parts` の順番を変え、`今は${rr.count}回続けて書かれています。合計${rr.total}回にします` を一番上・一番大きく（18px・太字）する。その下に「1回目／2回目／全体」（16px）、その下に1回目の命令の行（14px。**Safety P2-3 のとおり畳まない**）。文・数はどれも今のまま（サーバーの `state.repeat_range` だけ）
- 案B（任意）：会話の吹き出しに出る同じ文は、文を変えずに文字を小さく・色を控えめにする（カードが主役になる）。**文を隠す・畳むはしない**。安全の担当に「隠していない」ことを確かめてもらう
- 動画では、台本 Ver.7.2 案の字幕「いま2回くり返している動きを、3回にする案。範囲は人がボタンで決める」で補う
- 合格の線：S3 で、「合計3回にします」の行が範囲のカードの1行目にあり、［この範囲を繰り返す］と同時に見える（両方の画面サイズ）

## 3. 3D の高さ 6px の差は実害があるか
**結論：実害なし。**
| 版 | 画面 | 3D の枠 | 点の広がり（実際に描かれた図形） |
|---|---|---|---|
| 434165d | 1440×900 | 738×492 | 734×577 |
| 9417ac8 | 1440×900 | 872×481〜486 | 717×564（**約2%小さいだけ**） |
| 434165d | 1280×720 | 689×230 | 343×269 |
| 9417ac8 | 1280×720 | 775×300 | 447×351（**約30%大きい**） |
- 枠は幅が 134px 広く、面積は約17%広い。図形の大きさは高さで決まるが、差は約2%で、目では分からない
- どちらの版でも、点の広がりが枠より大きい（区間に寄せているため。上の V1）。見やすさを決めているのは 6px ではなく、V1 のほう
- e2e の決まりは「幅も高さも 434165d より小さくしない」。**6px のために配置を崩さない**ことをすすめる
- **決定（唐川さん 11/4）：今回だけの例外として記録し、テストの基準は変えない**
