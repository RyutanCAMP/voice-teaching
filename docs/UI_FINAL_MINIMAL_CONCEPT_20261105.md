# Voice Teaching 本番UI：ミニマルデザイン確定案（2026-11-05 夜）

> 唐川さんが画面の赤入れをした後、ChatGPTで作成した**最新の完成イメージ**を実装するための引き継ぎ。PR #4 の既存コードにそのまま合格判定を出したものではない。**この決定を勝手に旧案へ戻さないこと。**

## 目指すUI
- **文字が多すぎる画面はNG。ほぼアイコンと必要最小限の情報だけ。**
- 画面はダークネイビー＋青の統一感、選択点／変更差分はオレンジ。余白を広く、映画のように洗練された印象。
- 3D軌跡・位置番号を中央〜右に**可能な限り広く**表示。ロボット本体の実動作と混同しない。
- 左の会話ペインは細く、音声入力が主役。マイクは左下に大きく表示し、**何度でも連続して押せる**こと。テキスト入力は小さなキーボードアイコンで展開。
- アシスタントの丸アイコンは **AIではなく「VT」**。アプリ名は **Voice Teaching**。
- **正面に戻す**（視点リセット）ボタンは必ず3D領域に残す。カメラ視点だけを戻し、ジョブ編集・座標や承認状態を変えない。

## 消す／折りたたむ（通常画面）
- ヘッダーの長いキャッチコピー、JOBファイル名やロボット機種名の常時強調、オンラインの大文字表示。
- 3D / Y-Z / X-Z / X-Y の大きな文字タブ。必要なら設定メニューまたはコンパクトアイコンへ。
- 右の巨大な「変更内容」常設ペイン。**変更が必要なタイミングだけポップアップ**で見せる。
- 座標・移動量の長い説明と安全の注意文の反復、動画の再生速度 x0.5/x1/x2、冗長なプレビュー説明ラベル。
- フッターの説明文・装飾的なラベル。必要な注意は適切な操作時に、内容が読める形で表示する。

## 残す（必須）
- 上部に Voice Teaching ロゴ、設定／メニューのアイコン。
- 会話履歴（ユーザーの発話は青、VTからの応答は短く・読みやすく）。
- 発話時に大きなマイク、録音中／処理中／音声認識失敗の状態が一目で分かること。
- 広い3D：点・軌跡・C00005等の位置番号、選択位置と変更差分の強調。
- **正面に戻す**アイコン。必要に応じ再生アイコンも目立ちすぎないサイズで。
- 安全拒否、あいまいな方向確認、旧セッション失効、停止理由、変更前後差分と人による承認。**必要なときは明確なダイアログ表示**。安全に不可欠な情報を「目につかないヘルプ内」へ移してはいけない。
- ジョブ読み込みから操作開始、候補確認→承認→出力の一連の撮影フロー。

## 候補ができたときだけ出るポップアップ
- 背景の3Dが見える状態でコンパクトに表示。
- 対象位置：例 C00005
- 方向：例 Z−
- 移動量：例 3mm
- 差分：例 Z 200.000 → **197.000**（X/Yも確認できるよう必要時に表示）
- 安全上の必須注意、停止条件、承認者入力とボタン（**安全検証合格後のみ有効化**）、戻る／閉じる。
- ボタンの活性・非活性はサーバーの真の状態と一致。UIだけで承認不可状態を解除しない。
- ポップアップを閉じても**既存候補が残り承認できる問題（P0）を放置しない**。取消・言い直し時はサーバー側で失効させる。

## 独立した実装注意
- この画像は**完成イメージ（モック）**であり、現行プログラムの完成証明ではない。
- UIの文字削減は、必要な安全説明まで削る指示ではない。**通常時は最小限、危険時と承認時は明瞭に**がルール。
- シクロ：P0（取消・言い直し後の古い候補）を修正、安全レビューの後、本番UIと音声認識を統合する。
- クローク：方言、誤認識、発話の途中切れ、自然な言い直しを実Claude APIで検証。未確認の軸/方向/量/単位を勝手に補完して候補確定させない。
- デバッグ版8825で承認・出力が無効ならその保護を維持する。実機の自動動作・転送を試験しない。
- 撮影は1920×1080。**起動直後のUIから録画**。ダミーJOBで30mm拒否→5mm候補→差分確認→画面承認→出力はP0解消・最終確認後。
