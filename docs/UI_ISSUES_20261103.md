# 操作して分かった重要な改善課題（2026-11-03 夜・家のPC・唐川さんの声）

記録：シクロ。根拠は、唐川さんが家のPCの Google Chrome で、実際の声と本物の Claude（claude-sonnet-5-5）で操作した結果と、
同じ指示をプログラム（モックの解釈）で再現した結果。対象のコード：`feat/claude-talk` 1cc31dc（＋ `fix/mic-single-shot` 3d8d773）。

## 1. 起きたこと
- 3D で C00001 を選び、「ここの位置を3ミリ下げてくれる」と話した
- 返ってきたのは「どの動きのことか、プログラムで確かめられませんでした」（Claude に聞く欄の文）
- 音声認識はかなり正確だった。**アプリが言葉を理解できず、自然な指示が通らない**のが問題
- 「Claude に聞く」（左下）と、右の音声の指示が分かれていて使いにくい

## 2. 原因（4つ。重なっていた）
| # | 原因 | 種類 | 確かめ方 |
|---|---|---|---|
| A | **声が「Claude に聞く（読み取りだけ）」の欄に入った**。準備のときにシクロが「🎤 で聞き取った文を、この欄に入れる」に印を付けていた（Scene 3 の説明の確認のため）。読み取りだけの欄なので、位置の変更にはならない | 入口が2つ（設計） | 画面の準備の手順（scratchpad の open_for_user.py） |
| B | **「ここの位置」が読めない**：指示の欄でも「「位置」が分かりませんでした」と聞き返す。「この位置」「ここ」は読めるが、「ここの位置」は「ここ」＋読めない言葉「位置」になる | 言葉の読み方（キーワードの表に無い） | WebFlow で C00001・C00002・C00005 とも同じ |
| C | **上下の向きが「未確認」**（家のPCに `records/updown.json` が無い）：「この位置を3ミリ下げて」も「上下の向きがまだ確認されていません。Zプラス・Zマイナスのように…」と聞き返す。安全の決まり（M2）どおり | 設定（安全の決まり） | 同上。「Zマイナス3ミリ」なら通る |
| D | **C00001 は変更できない位置**：DEMO_BUTTON_REPEAT の C00001〜C00003 は、くり返しの中で2つの命令が共用（21・24行目など）。C00000・C00004 は MOVJ。**このデータには変更できる位置が1つも無い**。「Zマイナス3ミリ」でも、参考の候補（承認できない・理由を赤で出す）になる | 位置の制限（安全の決まり） | shift_check：「2つの命令が共用しているため…変更しません」 |

- **「意味が分からない」（B・C）と「変更できない」（D）は、今もプログラムの中では別の結果**（聞き返し／止まった候補と理由）。ただ、A のため唐川さんの画面ではどちらも出なかった
- 変更できる位置のあるサンプル：`DEMO_C_PLACE.JBI`（C00001〜C00006）、`DEMO_PLACE.JBI`（C00001〜C00005）。C00005 で「Zマイナス3ミリ」→ 候補 Z −3.000（承認できる）まで確かめた。「ここの位置を3ミリ下げて」は B で、「この位置を3ミリ下げて」は C で聞き返しになる

## 3. 課題（優先順）
1. **入力を1つにする**（Step F）：「このロボット、何してる？」「ここを3ミリ下げて」「じゃあ3回にして」を、同じマイク・同じ入力欄から。会話の文脈・3D で選んでいる位置・指示の中身から、説明・位置の変更・回数の変更へ振り分ける
2. **自然な言葉の理解**：キーワードの表を増やすだけでなく、Claude に意図を構造化させる。ただし Claude の値は使わず、位置・軸・向き・量はプログラムが利用者の文と照らし合わせて確かめ、分からなければ人に聞く
3. **分からない理由を分けて伝える**：言葉が分からない／上下の向きが未確認／この位置は変更できない（理由と、変更できる位置の一覧）
4. **変更できる位置を先に見せる**：位置を選んだ時点で「この位置は変更できません（2つの命令が共用）」と出す。3D と位置の一覧で、変更できる位置が分かるようにする
5. 再現テスト：C00001（共用）で「ここの位置を3ミリ下げて」→「変更できない」と分かる／C00005（変更できる）で同じ指示 → 上下の確認があれば候補まで（無ければ上下の確認を求める）
