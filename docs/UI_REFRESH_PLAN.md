# 画面の仕上げの案（feat/ui-refresh）

- 依頼：唐川さん（2026-11-03）「近未来的でシンプル。音や演出に少しレトロな遊び心」。MotoSim のような多機能の画面にはしない
- 土台：f783b2f（feat/ui-refresh）。安全修正（内部レビュー中）は混ぜていない
- 状態：**案**。判定は QA Reviewer と Safety & Spec Reviewer が行う。サブエージェントのレビューは同じ Claude であり、外部の独立レビューの代わりにはならない

## 1. 方針

- 今の方針（Apple のように落ち着いた画面・5秒で分かる・目立たせる操作は1つ）はそのまま
- 3D の図を主役にする。操作の欄は右（狭い画面では下）に控えめに
- 「近未来」は色と余白で出す（図の地・四隅の細い印・等幅の文字）。「レトロ」は効果音（矩形波・三角波の短い音、既定 OFF）と等幅の番号だけ
- 安全の表示（赤い「承認できません」の帯・承認ボタン・注意の文）は、どちらのテーマでも弱めない
- 新しい機能（回数の変更など）は足していない。画面の文に、安全や距離を断定する言葉を使っていない。承認はボタンだけのまま

### 2.1 3D の名前の重なり（シクロの指摘）

実機の参考ジョブ（同じ値の2点 C00000 と C00006）で、止まった候補の確認表示の 3D に「Z −3.000mm」が「C00000」の名前に重なっていた。

- 直し方：名前・変更量の文字を置く前に、すべての点（±9px）・変更後の点の輪（r=14）・右上の拡大の窓・図の外を「置かない所」にし、近くの4〜6か所から空いた所を探す。無ければ 30〜60px 離した所に置き、細い引き出し線でつなぐ
- 確かめ方：実機のジョブは使わない。e2e の中で、架空の DEMO_C_PLACE から C00006 を C00000 と同じ値にしたジョブを作り（`same_pos_job()`）、C00000（承認できない）・C00006（承認できる）を Z −3mm／+10mm にして、図と確認表示で名前・点・変更後の点の輪の四角が重ならないことを見る
- 先に確かめたこと：直す前は3件とも NG（`名前 C00000` と `変更後の点` など）。直したあと3件とも OK

## 3. 2回→3回の表示の案（**未実装**）

回数の変更は feat/repeat-count で別の担当が作っている途中。**画面には出していない**（実装済みに見せない）。絵は `docs/ui-refresh/mock_repeat_count_UNIMPLEMENTED.png`（「デザイン案・未実装」と大きく書いた絵。元は同じ名前の .svg）。

ここに出す案：

1. **右の候補のカード**（今の「Y方向に −3.000mm」の所）に、大きく「2回 → 3回」。その下に「1回目・2回目・3回目」の小さな札を並べ、増える回だけオレンジの点線の枠
2. **3D の図の左上**に小さな札「くり返す区間（○行目〜○行目） ×2 → ×3」。くり返す区間の線を太く、ほかの区間は薄く。線を3本重ねて描くことはしない（回数を線の本数で見せると、経路の目安と取り違えやすいため）
3. **確認表示**の見出しは1行「くり返しの回数を 2回 から 3回 に変えます」（数はサーバーの候補の値をそのまま。Claude の文に数を書かない）
4. 変わる行の書き方（JBI の命令）は、仕様が決まってから。分からない形は止める側にする

決めてほしいこと：回数を変える命令の形（どの行のどの値か）、止まった候補のときの札の色（灰にする案）。

## 4. テーマの色

- 画面の色は `style.css` の変数。OS がダークのときの組（`@media (prefers-color-scheme: dark)`）と、ダークを選んだときの組（`:root[data-theme="dark"]`）は同じ値（node のテストで同じことを確かめる）。JS より先に CSS で色が決まるので、開いたときにちらつかない

## 5. 音

- 既定は **OFF**。「？」の小窓の ON を押したときだけ鳴る。`localStorage` の `vt-sound` が `on` のときだけ（ほかの値・読めないときは OFF）。OFF の間は Web Audio も作らない
- Web Audio で作る短い音（音のファイルは入れない）。音量 0.035、長さ 0.3 秒まで

| 時 | 音 |
|---|---|
| JOB を読み込んだ | 三角波 660 → 990Hz の2音 |
| 承認できる変更候補ができた | 矩形波 880Hz の短い2音（**止まった候補では鳴らさない**） |
| 承認した（サーバーが受け付けたあと） | 三角波 ド・ミ・ソ |

- マイクが ON の間（聞いている・聞き直しを待っている）は鳴らさない（音を声として拾わないように）。`new Sfx(() => recording() || state.live)`
- 音は合図だけ。承認・出力は呼ばない。音が出なくても画面と承認ボタンの働きは同じ

## 6. 演出

- JOB を読み込んだとき、3D の点が命令の順に現れ、直線（MOVL）の区間が引かれる。全体で 1 秒以内（e2e で 760ms）
- 点の位置・線の形・色の属性は変えない（透明度と線の引き方だけ）。点線・破線（MOVJ・目安の区間）は形を変えずに現れるだけ
- `prefers-reduced-motion: reduce` のときは演出しない（JS で止め、CSS の指定も `no-preference` のときだけ）
- ロボット本体の絵は描かない

## 7. 確かめ方

- `node --test tests/theme.test.mjs`：テーマの決め方、両方のテーマのコントラスト、OS のダークと選んだダークが同じ値、止まった候補がオレンジでない、音は既定 OFF・マイク ON で鳴らない・3つだけ
- `python -m pytest -q tests/test_ui_refresh.py`：配信、音のファイルが無い、鳴らす所が3つ、切り替えが小窓の中、演出の長さと reduced-motion
- `python tools/e2e_browser.py` の `check_ui_refresh`：OS のダークに合わせる → ライトに切り替え → 覚えている、ダークでの赤い帯・注意・承認ボタンのコントラスト、音は既定 OFF → ON を覚える → 止まった候補では鳴らない、演出は 1 秒以内・reduced-motion で出さない、同じ値の2点の名前の重なり
- スクリーンショット：変更前（f783b2f）と変更後（ライト・ダーク、1280px・390px）。代表は `docs/ui-refresh/after_*.png`
