# 「このJOBは何をしているの？」の解説：設計（M1〜M3 の修正のあとに実装）

書いた人：シクロ（会社の PC）。2026-11-03。
きっかけ：唐川さんの指示（安全修正のあと、次に優先する機能）。CHECKER_025 その1 5章⑤と、CHECKER_026 7章 LATER。
状態：**設計だけ**。実装は M1〜M3 の再レビューに出したあとに始める。

## 1. 何をするか（1行）
「このJOBは何をしているの？」と聞くと、命令の並びを短い文で説明する。どの文にも根拠の命令の行が付き、その文を押すと行と3Dの点が光る。**ジョブは一切変えない。**

## 2. 変えないこと（安全の線引き）
- 説明だけを行う。変更の道具（propose）は渡さない。候補・承認・出力の状態は変えない
- 承認待ちの候補があっても説明はしてよい。ただし説明の中から変更は始めない
- Claude に送ってよいのは合成ジョブだけ（`sim._is_synthetic`）。送るのは命令の行（//INST）と行番号、位置番号の一覧。座標の値（//POS）は送らない
- 合成ジョブでないときは Claude を呼ばない。プログラムの決まった文（話し手「アプリ」）で、命令の事実だけを並べる
- 数字（座標・距離・速度の値）は Claude の文に入れさせない。出すなら、プログラムが行から取り出して入れる
- 「安全です」「当たります」「干渉します」は使わない。禁止語の検査（`contains_forbidden`）に引っかかったら、その文は決まった文に置き換える
- DOUT や TIMER の意味を断定しない。「信号を切る」「3秒待つ」のように命令の事実を書く。「つかむ」「離す」と読める場合は「推定」と明記する（8章で決める）

## 3. 流れ
```
「このJOBは何をしているの？」
 ① プログラム：説明を頼む言い方か判定（決めた一覧の言い方だけ。B1・B6 の検査は先に通す）
 ② 合成ジョブ → Claude に説明を頼む（道具 explain_job）／それ以外 → プログラムの決まった説明
 ③ プログラムの照合：行番号・位置・文の検査（5章）。通らない文は捨てる。全部捨てたら決まった説明に戻す
 ④ 画面：説明のカード（最大8文）。各文に根拠の行（プログラムが行の中身から作る）
 ⑤ 文を押す → 3Dでその位置の点を光らせ、JOB の行を光らせる（今の位置の強調の仕組みを使う）
```

## 4. Claude に頼む形
- 道具 `explain_job`（strict、`additionalProperties: false`）
  - `steps`：1〜8件。各件は `summary`（短い文。最大60文字）、`lines`（根拠の命令の行番号。1〜5件）、`positions`（位置番号の一覧の enum。0〜3件）
  - ほかの項目は受け取らない
- システムの文：「説明だけをする。変更を提案しない。数字を書かない（位置番号は positions に入れる）。安全・距離・干渉を断定しない。信号の意味は推定と書く」
- モック：今の `mock_locate` と同じ決まった規則で、命令の並びから説明を作る（MOVJ/MOVL で位置へ移動、DOUT ON/OFF、TIMER）。画面に「モック（テスト用）」と出す

## 5. プログラムの照合（Claude の答えをそのまま使わない）
- `lines` がすべて命令の行の範囲にある
- `positions` がジョブの位置の一覧にあり、そのどれかを参照する行（`MOVL C00005 …`）が `lines` に入っている
- `summary` に数字があれば捨てる（位置番号は positions から、プログラムが文の前に付ける）
- `summary` が禁止語の検査に通らなければ捨てる
- 文の並びは行番号の順に並べ直す。重なった文は1つにまとめる
- API の失敗・拒否・形の違う答え → 決まった説明だけを出す（「Claude での説明ができませんでした」と明記）

## 6. 画面
- カード「このジョブの流れ（Claude の説明・未確定）」。各行は「① C00002 へ直線移動 → 信号を入れる（つかむ動作と推定）」＋根拠の行（小さく）
- 押した文の位置を3Dで光らせる。MOVJ の区間は、MOVJ の表示の修正（S-MOVJ）の「関節移動」の見た目のまま（直線にしない）
- 話し手の表示：Claude／モック（テスト用）／アプリ
- カードは読むだけ。ボタンは［閉じる］だけ

## 7. 受入テスト（先に書く）
1. DEMO_C_PLACE で「このJOBは何をしているの？」（偽の Claude）→ 説明のカード。根拠の行がファイルの行と一致。ジョブ・候補・承認は変わらない
2. 偽の Claude が範囲外の行・関係の無い位置・数字入りの文・禁止語・9件以上・余計な項目を返す → その文を捨てる。全部捨てたら決まった説明
3. 合成でないジョブでは Claude を呼ばない（呼んだ回数 0）。送る内容に //POS・座標の値が無い
4. 承認待ちの候補があるときも説明は出る。候補と承認は変わらない。説明の後の「そうそう」で何も選ばれない
5. 「このJOBの3mm下げて何をしているの」など、変更の言葉が混ざる → 今の判定（聞き返し・止める）が先に動き、説明はしない
6. 文を押すと、3D の点と行が光る（e2e）
7. API の例外 → 決まった説明と「できませんでした」の文

## 8. 唐川さんに決めてほしいこと
1. DOUT ON/OFF を「つかむ／離す（推定）」と書いてよいか。案：書くときは必ず「推定」を付ける。付けないなら「信号を入れる／切る」だけにする
2. 説明を頼む言い方の一覧（「このJOBは何をしているの」「何をするジョブ」「流れを説明して」…）
3. 合成ジョブでない JOB（実機の JOB）は、決まった説明だけでよいか（Claude に送らない今の決まりのまま）
