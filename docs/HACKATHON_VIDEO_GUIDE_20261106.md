- ハッカソン期間中に制作したプロジェクトのみ対象。既存コード不可。

## ガイドの要点
- デモ動画は審査員へのプロジェクト発表で最重要。審査員はすべてのライブアプリを直接操作できないので、課題、技術的解決策、実装を明確に伝える。
- コード説明に終始せず、主要機能と動作を強調。審査基準を意識し、「もっと見たい」と思わせる。
- 画面録画ツール例：QuickTime（macOS）、Loom、OBS Studio、Cap.so。これらの利用は必須ではない。
- 音声：可能なら外付けマイク/高品質ヘッドセット、静かな環境。
- 映像：最低1080p、UI・テキストが読める画質。録画前に全画面・プレゼンテーションモード、不要なDock/タスクバーを隠し、おやすみモードで通知を防ぐ。
- 最終動画を冒頭から最後まで視聴し、音声と映像の同期を確認。
- YouTube限定公開または閲覧可能なGoogle Drive/Loomリンクを貼る。リンクを知っている全員が視聴可能な設定にし、別アカウント/ログアウト状態で試す。
- CVプラットフォームでログイン→Submit Project→必要項目入力→提出→View Submissionのステータス確認。
- 提出前に全チームメンバー、GitHub公開状態、動画時間・権限を確認。締切より余裕を持って提出。
- 動画が3分を超えても受付自体はされ得るが、審査員は制限時間で視聴を終えるため、最重要ポイントを冒頭に置く。

## Voice Teaching向け3分構成案（撮影時に調整）
| 時間 | 見せるもの | メッセージ |
|---|---|---|
| 0:00–0:20 | 現場のロボットと開発者 | ロボットの位置調整には専門知識と慎重な確認が必要 |
| 0:20–0:40 | JOB読込・3D表示 | 既存JOBを読み込み、どの位置を編集するか直感的に確認 |
| 0:40–1:20 | 自然言語の指示とAI応答 | 「Y方向に10mm」などの指示を変更候補へ |
| 1:20–1:55 | 差分表示・承認 | 人の承認なしには変更を確定しない |
| 1:55–2:20 | 安全ガード・範囲外の拒否 | 1回20mm上限、累積範囲、構造検査を見せる（実装とテストが確認できた機能のみ） |
| 2:20–2:40 | JOB出力・実機の様子 | 確認済みの出力・実機動作のみ映す |
| 2:40–3:00 | 開発背景と締め | 制御設計・現地試運転28年の経験を使い、現場で使いたくなるUIを目指した |

※ 尺は最大3分。映像・音声の品質を優先し、未検証の安全性や実機動作を誇張しない。平日通常業務8時間を続けながら短期開発した点はエンディング候補。制作日程は「構想1日、設計2日、デバッグ・試運転1日、動画撮影2日、編集・まとめ1日」の本人メモを基準に、実際の進捗に合わせて表現を確定する。
