# 実機で分かったこと：JBI の位置番号（C）は、命令ごとに別の番号にする（2026-11-06）

- 確かめた人：唐川さん（YRC1000 のコントローラーに、ジョブのファイルを読み込んで確かめた）
- 記録：シクロ（会社PC）。**唐川さんの指示で、重要な事実として共有する**
- 実機で教えたジョブの中身（座標の値）は、このリポジトリに入れない決まり（CLAUDE.md）なので、ここには書かない。ファイルは唐川さんの PC の中だけにある

## 1. 分かったこと
| JBI の書き方 | コントローラーへのロード |
|---|---|
| 回数を2回・3回にするために、**同じ位置番号（例 C00001〜C00005）を、複数の命令で使い回した** | **データエラー**（読み込めない） |
| **命令1つごとに別の位置番号**を付けた（2回目は、1回目と同じ値を新しい番号 C00006〜C00010 に写した）。`///NPOS` を位置の数に合わせた | **読み込めた** |

- どちらも、元のジョブ（ロボット座標・`MOVJ` で始まり `MOVL` 5つ・`MOVJ` で終わる・END）から作った。位置の値・速度・ヘッダー・改行（CRLF）・文字（ASCII）は同じで、違いは位置番号の付け方と `///NPOS` だけ
- 元のジョブでも、同じ値の最初と最後の位置は、別の番号（C00000 と C00006）になっていた。ペンダントで教えると、命令1つごとに新しい番号が付く
- 「同じ番号を使い回すとデータエラー」は、**この1件の実機での確認**。エラーの番号・どの決まりに当たったか（使い回しそのものか、`///NPOS` との関係か）は、まだ確かめていない

## 2. 読み込めた形（例：5つの位置の組を2回）
```
///NPOS 12,0,0,0,0,0          ← 位置の数（C00000〜C00011）
C00000=<最初の位置>
C00001〜C00005=<1回目の5つの位置>
C00006〜C00010=<1回目と同じ値を写したもの>
C00011=<最後の位置>
...
MOVJ C00000 ...
MOVL C00001 ... 〜 MOVL C00005 ...   ← 1回目
MOVL C00006 ... 〜 MOVL C00010 ...   ← 2回目（番号は別・値は同じ）
MOVJ C00011 ...
END
```

## 3. Voice Teaching への影響
- 今の回数の変更（`jbi.Job.plan_repeat`・`sim` の回数の出力・`docs/REPEAT_COUNT_DESIGN.md`）は、**同じ位置番号の行を複写する**作り。合成ジョブ `samples/dummy/DEMO_BUTTON_REPEAT.JBI` も、C00001〜C00003 を2回使っている。回数の変更の出力（`DEMO_BUTTON_REPEAT_SIM.JBI.txt`）も、同じ番号を3回使う
- **この形は、実機のコントローラーでは読み込めない形**と分かった
- 今すぐの害：シミュレーション用の出力は `.JBI.txt` で、実機に入れない決まりなので、無い。ただし、仕様の前提（「同じ行を足せば回数が変わる」）が、実機の決まりと食い違っている
- これからの扱い（提案。決めるのは唐川さん）
  1. 回数の変更の設計（REPEAT_COUNT_DESIGN）に「実機では、命令ごとに別の位置番号と `///NPOS` の更新が要る」を書く
  2. 合成ジョブ・e2e・受入基準で、位置番号の使い回しを「実機では読めない形」として扱う（シミュレーションの表示には使えるが、実機の形の手本にはしない）
  3. 将来、実機の形に近い出力を考えるときは、番号を付け直す（値は写す）作りにし、変更のあとの検査（新しい移動の区間が無い・違いは足した回だけ）を、番号が違っても同じ値なら同じ位置として比べる形に直す
  4. 位置番号・`///NPOS`・ジョブ名など、実機の JOB の決まりは推測で決めず、こうした実機での確認を記録して使う（CLAUDE.md の「分からないロボットの仕様は推測で決めない」）
