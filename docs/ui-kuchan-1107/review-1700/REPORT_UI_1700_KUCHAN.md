## 2. 動画に効く問題と提案（優先順）

### UI-1700-1（P1・動画）：1920 で、承認のあと、変更の点とオレンジの線がポップアップに隠れる
- 実際：承認のあと `body.vt-approved` で、ポップアップが 3D の右下に戻る（style.css 末尾「承認のあと（1500px 以上）」・app.js 1420）。DEMO_RJ_XYZ の C00004 を Z+5 の場面で、C00003・C00004・C00005 と変更の線が隠れる（`1920x1080_2_approved.jpg`・`_3_saved_ok.jpg`）。**動画の「承認→保存」の場面**
- 期待：承認・保存の場面でも、動かす点と変更の線が見える（承認の前と同じ）
- 提案 A（おすすめ・CSS 1つ消すだけ）：「承認のあと（1500px 以上）」の `body.vt-approved .cand-pop {…}` を外す。承認のあともポップアップは会話の欄の上（K1）。会話の欄に選ぶボタンが出たとき（保留など）は K1 の例外で 3D の右下に戻るので、押す必要のあるボタンは隠れない
  - 代わりに起きること：承認のあとの質問への答えの吹き出し（ボタンの無いもの）が、ポップアップの下になる。［承認して保存］が1回になれば、承認のあとはすぐ保存の結果なので、影響は小さい
- 提案 B：今のまま（右下）にして、撮影では、ポップアップと重ならない視点（［正面に戻す］のあと少し回す）にする。コードは変えない
- **判断：シクロ（コードの持ち主）と唐川さん（動画）**

### UI-1700-2（P1・保存の成否の表示）：保存できたとき「✓」が2つ、取りやめたときも見出しが「✓ 出力しました」
- 実際（3つとも 1920・1440・1280 で同じ）：
  - 保存できた：「✓ シミュレーション用に出力しました」＋「✓ 選んだ場所に保存しました：…」（成功が2回）
  - 取りやめた：見出しが「✓ シミュレーション用に出力しました」、その下に「保存の場所への保存は取りやめました（…失敗ではありません）」
  - 窓が無い：見出しが「✓ …出力しました」、その下に［ダウンロードとして保存］（押すまでダウンロードされない＝正しい）
- 17時の指示「保存先・ファイル名・保存成否の誤表示」「サーバーの出力とブラウザーの保存を二重に成功と報告しない」（追加指示 B）に当たる
- 提案（app.js の文の並べ方だけ。中身・判定は変えない）：**見出しはユーザーの保存の結果1つだけ**にし、サーバーの記録は灰色の小さな1行（✓ を付けない）
  - 保存できた：「✓ 保存しました　{ファイル名}（選んだ場所。中身を照らし合わせて確かめました）」
  - 取りやめた：「保存を取りやめました。承認はそのままです。［保存先を選んで保存］［ダウンロードとして保存］」（灰色・失敗の赤にしない）
  - 窓が無い：「保存の場所を選ぶ窓を使えません。［ダウンロードとして保存］」→ 押したあと「↓ ダウンロードしました　{ファイル名}（場所はブラウザーのダウンロード先）」
  - 共通の下の1行（灰色）：「アプリの記録：{ファイル名}（output/sim）」
- ［承認して保存］に一体化したあとも同じ言い分けが要る（詳しくは `../approval-save/APPROVAL_SAVE_DESIGN_KUCHAN_1107.md` 4章）
