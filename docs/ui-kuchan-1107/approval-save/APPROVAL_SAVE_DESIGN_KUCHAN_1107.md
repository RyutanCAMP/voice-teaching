## 1. 考え方（3つ）

1. **何を承認するかを、押すボタンそのものに書く**：ボタンの文字が「**C00004 を Z +5.000mm で承認**」。対象・軸・符号・量を読まずに押すことがない。数はサーバーの候補の値をそのまま入れる
2. **承認と保存は、色も言葉も別の操作**：承認＝オレンジ（変更の色）、保存＝青。「承認したら出力される」と取り違えない。保存のボタンは「SIM ファイルを保存…」（「…」＝このあと保存先を選ぶ画面が開く）
3. **結果は、本当に起きたことだけを言う**：「保存しました（選んだ場所に書き込みました）」「ダウンロードしました（場所はブラウザーのダウンロード先）」「保存を取りやめました（承認はそのまま）」を言い分ける。キャンセルは失敗の赤にしない

## 5. シクロへの実装の注意（UI 側から見た安全の条件）

1. 承認のボタンの押せる／押せないは、**サーバーの候補の状態だけ**で決める（今のとおり）。UI の名前の入力だけで押せるようにしない
2. **押した瞬間に押せなくする**（連打・二重クリック）。応答が来るまで「承認しています…」。応答で状態を描き直す
3. ボタンの文字（対象・量）は、承認の要求に入れる候補の識別（トークン・リビジョン）と同じ候補から作る。**文字と違う候補を承認しない**（古い候補の文字が残る見え方を作らない）
4. 否定・訂正・位置の切り替え・JOB の読み直し・取り消しで承認が消えたら、保存のボタンは消して、承認のボタンに戻す（今の「保留」「取り消し」の表示はそのまま）
5. 保存の結果の文は、**書き込みの成功を確かめてから**出す（`showSaveFilePicker` の `close()` まで成功）。ダウンロードは「ダウンロードしました」まで
6. サーバーの output/sim への出力と、ブラウザーの保存を**二重に「保存しました」と言わない**（どちらを本物の保存にするかはシクロの設計。画面の文はどちらか1つ）
7. 確認表示（詳しく確認）の［承認する］は、**消すか、ポップアップと同じ1つのボタンにする**。2か所に別々の承認ボタンを置かない

## 6. K1 との関係（候補パネルを会話の欄に重ねる判断）
- K1（1500px 以上でもポップアップを会話の欄の上に重ねる）と、この提案はぶつからない。承認・保存のボタンはポップアップの下の段にあり、3D の差分は右に見えたまま
- 会話の欄に選ぶボタン（保留の［取り消す］［このまま残す］など）が出ている間は、ポップアップは 3D の右下に戻る（K1 の例外）。そのときも承認・保存のボタンはポップアップの中で見える（1920 の保留の場面で e2e で確認：P0 保留）
