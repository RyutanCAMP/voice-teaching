# 設計書：承認して保存（1つのポップアップで承認し、保存先をユーザーが選ぶ）

- 版：設計 v1（2026-11-06 夕方）。**実装の前。クロの Safety レビューを受けてから実装する**
- 書いた人：シクロ（会社PC）。依頼と決定：唐川さん（11/6）
- ブランチ：`feat/approve-and-save-1106`（土台 **60f3d24**＝撮影用シミュレーション版。60f3d24・8896 は変えない）
- 日時付きの出力（`feat/export-timestamp-1106` ba12bb2）は統合しない。その中の「承認1回につき出力1回」「F-B」の考え方は参考にするが、コードは持ち込まない

## 0. 目的と範囲
- 目的：保存先が分かりにくい（今は `output\sim\` に固定）ので、操作を「差分を見る → 名前を入れて［承認して保存］を1回押す → 保存先を選ぶ → 保存できたら完了」にする
- 範囲：シミュレーション用のファイル（`.JBI.txt`・中のジョブ名は `_SIM` 付き）の保存だけ。**実機用の `.JBI` の出力・ロボットへの転送・ロボットの起動は作らない**
- 変えないもの：解釈（Claude）・検査（check_proposal・上下の向きの照合）・候補の作り方・候補の世代（cand_gen）・取消／言い直し／保留／読み直しで承認を無効にする仕組み（stale.py・`sim.revoke`）・JOB の中身を作るときの確かめ（合成ジョブだけ・元との違いは承認した行と //NAME の行だけ）

## 2. 今の作り（60f3d24）
- 画面：候補のカード `#candidate-panel` の［確認して承認へ］（`#open-confirm`）→ 確認表示 `#confirm-overlay` で名前（`#approver-name`）→［承認する］（`#approve-button`）→ 候補のカードの［シミュレーション用に出力］（`#export-button`）
- サーバー：`POST /api/approve`（`flow.approve(sid, approver, candidate_gen)`：世代が今と違えば断る・名前が空なら断る・上下の向きの照合・止めた候補は承認しない）→ `e.approval`・`e.approval_gen = e.cand_gen`
- `POST /api/export`（`flow.export(sid, candidate_gen)`：今の世代と承認した世代が同じでなければ断る）→ `sim.export_sim(proposal, approval)` が `output\sim\<ジョブ名>_SIM.JBI.txt` を新しく作って書き（`open(.., "xb")`・上書きしない）、読み戻して照合 → `e.exported` にフルパス
- 承認を無効にする所：取消・言い直し・保留（`e.hold`）・読み直し・位置の変更・別の候補（`_invalidate`・`sim.revoke`・`cand_gen += 1`）。取り消した承認は `Approval.revocation.revoked` が立ち、直接 `export_sim` を呼んでも書かない

## 3. 新しい作り
### 3-1. 画面（1つのポップアップ）
候補ができたら、3D の上に出すポップアップ（新しい `#approve-save-panel`。今の候補のカードを置き換える）に、**承認の前に必ず見えるもの**を全部出す：
1. 対象の位置（例 C00005）・変更の向き（軸と符号）・変更量（例 +5.000mm）
2. 変更前→変更後の座標（X・Y・Z の表と、変わる値の強調）
3. 上下の向きの状態（確認済みなら確認した人・日時の1行。未確認なら「上下方向 未確認」）
4. 注意の箱（経路が変わる・検査を通ったことは物理的な安全の保証ではない など、今の候補の warnings）
5. 図の注意「この図で離れて見えても、当たらないとは限りません。腕やツールの根元は描いていません」（仕様 v2.1 4章）
6. 「シミュレーション用のファイルです。実機用の出力・転送・ロボットの起動はしません」
7. 承認者名の入力欄（必須。空なら［承認して保存］を押せない）
8. ［承認して保存］（1つだけ）。音声・文字の返事では押されない
- 1920×1080・1440×900・1280×720 のどれでも、1〜8 がスクロールなしで見えること（受入 A3）。60f3d24 の確認表示で 1280×720 が P2 になった問題をここで解く
- 回数の変更（repeat）の候補も同じポップアップ（対象の範囲・回数の前→後・足す／消す行）

### 3-2. 押したあとの流れ
```
［承認して保存］（ボタン1回＝承認）
  → POST /api/approve（今の確かめそのまま。成功したら承認 A を作る）
  → サーバー：A の JOB の本文を 1回だけ作る（今の export_sim の確かめと同じ）→ A に固定して持つ（bytes・sha256・ファイル名）
  → 画面：保存のダイアログ（showSaveFilePicker）を開く
      ・キャンセル → 「保存していません」。A は残る。［保存先を選んで保存］を出す（承認ではない）
      ・選んだ → GET/POST /api/save-payload（A の本文・sha256・ファイル名。同じ A なら何回でも同じもの）
               → 画面：sha256 を照合 → 選んだファイルに書く → 読み戻して sha256 を照合
               → POST /api/save-report（結果：ok / cancel / error・ファイル名・読み戻しの sha256）
               → サーバー：監査の記録を1行足す。ok なら A を「保存の報告あり」にする
  → 画面：保存の報告が記録されたときだけ「✓ シミュレーション用JOBを保存しました：<ファイル名>」
```
- 保存のダイアログは押した直後（ユーザーの操作の直後）でないと開けない。承認の応答のあとに開けなかったときは、［保存先を選んで保存］を出して、もう一度押してもらう（承認はやり直さない）
- **［保存先を選んで保存］は承認ではない**：A が今も有効（取り消されていない・世代が同じ・保留でない）ときだけ押せる。押してもサーバーで承認は増えない

### 3-3. サーバーの口（案）
| 口 | 中身 | 断るとき |
|---|---|---|
| `POST /api/approve`（今のまま） | 承認。成功したら、その承認の本文を1回だけ作って固定する（作れなければ承認も断る＝今の export の確かめ） | 今の条件すべて＋本文を作れない |
| `POST /api/save-payload`（新） | `session_id`・`candidate_gen` → 固定した本文（base64）・sha256・ファイル名（`<ジョブ名>_SIM.JBI.txt`）・承認の番号 | 承認が無い・取り消された・世代が違う・保留・画面が閉じた・**すでに保存の報告 ok がある** |
| `POST /api/save-report`（新） | `session_id`・`candidate_gen`・承認の番号・結果（ok／cancel／error）・ユーザーが付けたファイル名・読み戻しの sha256 | 承認が今のものでない・sha256 が固定した本文と違う（ok として受けない。error として記録） |
| `POST /api/export`（今の） | **使わない**（新しい画面からは呼ばない。サーバーに写しを書く道を残さないため、外すか、テストだけで使うかを実装のときに決める） | ― |
- 本文は承認のときに1回だけ作る。`/api/save-payload` は何回呼んでも同じバイト列を返す（D7）。違う本文を作る道は無い
- 本文を作るときの確かめは今の `export_sim` と同じ（合成ジョブ・承認した差分・元との違いは2行だけ・//NAME・`_NAME_OK`）。ファイルに書く部分だけを外す

### 3-4. 監査の記録（案B）
- 場所：`records/save_audit.jsonl`（git に入らない。1行1件・追記だけ）
- 1件の中身：`time`（日本時間）・`session`・`candidate_gen`・`approval_id`・`approver`・`job`（元のジョブ名）・`suggested_name`・`saved_name`（ユーザーが付けた名前。パスは入れない）・`sha256`・`event`（approved／payload／report_ok／report_cancel／report_error／refused）・`reason`
- **保存の報告は「ブラウザがそう言った」ことの記録で、物理的に保存された保証ではない**（D8）。画面の文も「保存しました（ブラウザの報告）」とし、記録の `event` も report_ok と書く
- フォルダのパス（USB の名前など）は記録しない（ブラウザからは取れない。個人の情報を残さない）

### 3-5. 保存できないブラウザ（代わりの方法）
- `showSaveFilePicker` が無いとき：ダウンロード（`<a download>`）で `<ジョブ名>_SIM.JBI.txt` を渡す
- ダウンロードは保存できたかが分からないので、**完了にしない**。画面は「ダウンロードを渡しました。保存されたかは、ブラウザのダウンロードの一覧で確かめてください」。記録は `event: download_handed`
- ユーザーが［保存できました］を押したら、それを「人の申告」として記録する（report_ok_by_user）。物理的な保存の保証ではない
- このアプリは音声のために Chrome を前提にしているので、ふだんは使われない道
