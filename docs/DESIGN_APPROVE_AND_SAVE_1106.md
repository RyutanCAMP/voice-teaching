## 0. 目的と範囲
- 目的：保存先が分かりにくい（今は `output\sim\` に固定）ので、操作を「差分を見る → 名前を入れて［承認して保存］を1回押す → 保存先を選ぶ → 保存できたら完了」にする
- 範囲：シミュレーション用のファイル（`.JBI.txt`・中のジョブ名は `_SIM` 付き）の保存だけ。**実機用の `.JBI` の出力・ロボットへの転送・ロボットの起動は作らない**
- 変えないもの：解釈（Claude）・検査（check_proposal・上下の向きの照合）・候補の作り方・候補の世代（cand_gen）・取消／言い直し／保留／読み直しで承認を無効にする仕組み（stale.py・`sim.revoke`）・JOB の中身を作るときの確かめ（合成ジョブだけ・元との違いは承認した行と //NAME の行だけ）

## 3. 新しい作り
### 3-1. 画面（1つのポップアップ）
候補ができたら、3D の上に出すポップアップ（新しい `#approve-save-panel`。今の候補のカードを置き換える）に、**承認の前に必ず見えるもの**を全部出す：
1. 対象の位置（例 C00005）・変更の向き（軸と符号）・変更量（例 +5.000mm）
2. 変更前→変更後の座標（X・Y・Z の表と、変わる値の強調）
3. 上下の向きの状態（確認済みなら確認した人・日時の1行。未確認なら「上下方向 未確認」）
4. 注意の箱（経路が変わる・検査を通ったことは物理的な安全の保証ではない など、今の候補の warnings）
5. 図の注意「この図で離れて見えても、当たらないとは限りません。腕やツールの根元は描いていません」（仕様 v2.1 4章）
6. 「シミュレーション用のファイルです。実機用の出力・転送・ロボットの起動はしません」と、**「USB に保存しても、ロボットのコントローラーに読み込まないでください（シミュレーション用・合成ジョブ）」**の1行（**M3**）
7. 承認者名の入力欄（必須。空なら［承認して保存］を押せない）。**前回の名前を自動で入れない**（ブラウザの自動入力も `autocomplete="off"` で止める）（**M8**・A25）
8. ［承認して保存］（1つだけ）。音声・文字の返事では押されない
- 1920×1080・1440×900・1280×720 のどれでも、1〜8 がスクロールなしで見えること（受入 A3）。60f3d24 の確認表示で 1280×720 が P2 になった問題をここで解く
- **ポップアップは、表示している候補の世代（candidate_gen）を持つ**。［承認して保存］はその世代を送る。状態が変わったら（世代が変わる・保留・画面が閉じた）ポップアップを描き直し、描き直すまで押せなくする（**M8**・A24）
- 回数の変更（repeat）の候補も同じポップアップ。足す行が多いと 1280×720 で全部は見えないので、**必ず見えるもの**（対象の範囲・回数の前→後・足す／消す行の数・注意・名前・ボタン）と、開いて見る詳しさ（足す行の全文）を分ける（S3）

### 3-2. 押したあとの流れ
```
［承認して保存］（ボタン1回＝承認）
  → POST /api/approve（今の確かめそのまま＋合成ジョブだけ（M1）。成功したら承認 A を作る）
  → サーバー：A の JOB の本文を 1回だけ作る（今の export_sim の確かめと同じ。M7）→ A に固定して持つ（bytes・sha256・ファイル名・approval_id）
  → 画面：状態を見て A が有効なら、保存のダイアログ（showSaveFilePicker、suggestedName＝<ジョブ名>_SIM.JBI.txt）を開く。無効なら開かない（M8）
      ・キャンセル → 「保存していません」。A は残る。［保存先を選んで保存］を出す（承認ではない）
      ・選んだ → 名前が _SIM.JBI.txt で終わるか確かめる（M2。違えば書かない）
               → POST /api/save-payload（A の固定した本文・sha256・ファイル名。同じ A なら何回でも同じもの。上下の向き・合成ジョブを関数の中で確かめる：M1・M4）
               → 画面：sha256 を照合 → **書く直前に POST /api/save-check で A がまだ有効か確かめ、無効なら書かない**（M5 ①）
               → 選んだファイルに書く → 読み戻して sha256 を照合
               → POST /api/save-report（結果：ok / cancel / error・ファイル名・読み戻しの sha256。サーバーも名前を M2 で検査）
               → サーバー：監査の記録を1行足す。ok なら A を「保存の報告あり」にする。A が無効なら断り、report_after_revoke を記録（M5 ③）
  → 画面：保存の報告が記録されたときだけ「✓ シミュレーション用JOBを保存しました（ブラウザの報告）：<ファイル名>」と、M3 の1行と「USB の場合は、取り外しの操作をしてから抜いてください」（S6）
  → 報告が断られた（書いたあとに A が無効になっていた）→ 「✓」を出さず、赤で「保存の途中で承認が無効になりました。保存したファイル <名前> は使わないでください」（M5 ②）
```
- 保存のダイアログは押した直後（ユーザーの操作の直後）でないと開けない。承認の応答のあとに開けなかったときは、［保存先を選んで保存］を出して、もう一度押してもらう（承認はやり直さない）
- **［保存先を選んで保存］は承認ではない**：A が今も有効（取り消されていない・世代が同じ・保留でない）ときだけ押せる。押してもサーバーで承認は増えない
- **ブラウザが本文を受け取ったあとは、サーバーは書き込みを止められない**（M5）。できるのは、書く直前の確かめで窓を小さくすること（確かめと書き込みの間は 0 にならない）と、書いてしまったときに人に知らせること。書いてしまったファイルは、サーバーもブラウザも消さない（消すのは人）
- **報告が届かなかったあとの2回目の保存**（M6）：サーバーは承認ごとに payload を渡した回数を数えて記録する。2回目からの payload の答えには「前に渡した回数」を入れ、画面は書く前に「前の保存の結果が分かりません。保存先にファイルがあるか確かめてから、もう一度保存してください」を出す（同じ中身の2つ目のファイルになりうるため）。**「承認1回につきファイル1つ」はサーバーでは保証できない**（中身は同じ）

### 3-3. サーバーの口（案）
| 口 | 中身 | 断るとき |
|---|---|---|
| `POST /api/approve`（今のまま＋） | 承認。**合成ジョブ（`sim._is_synthetic`）でなければ断る**（M1）。成功したら、その承認の本文を1回だけ作って固定する（作れなければ承認も断る＝今の export の確かめ） | 今の条件すべて＋合成ジョブでない＋本文を作れない |
| `POST /api/save-payload`（新・**POST だけ**。S4） | `session_id`・`candidate_gen`・`approval_id` → 固定した本文（base64）・sha256・ファイル名（`<ジョブ名>_SIM.JBI.txt`）・前に渡した回数 | 承認が無い・取り消された・世代が違う・保留・画面が閉じた・**合成ジョブでない（関数の中で確かめる。M1）**・**上下の向きの設定が承認のときと違う（関数の中で `_updown_unchanged` と同じ確かめ。`_run` の後の `_sync` に頼らない。M4）**・`approval_id` が違う・**すでに保存の報告 ok がある**・GET・よその Origin（S4） |
| `POST /api/save-check`（新・POST だけ） | 書く直前の確かめ。`session_id`・`candidate_gen`・`approval_id` → 有効か（理由） | payload と同じ条件で「無効」と答える（M5 ①） |
| `POST /api/save-report`（新・POST だけ） | `session_id`・`candidate_gen`・`approval_id`・結果（ok／cancel／error）・ユーザーが付けたファイル名・読み戻しの sha256 | 承認が今のものでない（→ `report_after_revoke` を記録し、画面に M5 ②の文）・sha256 が固定した本文と違う（ok として受けない。error として記録）・名前が M2 の検査に通らない（ok にしない）・上下の向き・合成ジョブ（M1・M4） |
| `POST /api/export`（今の） | **外す**（S5。サーバーが `output\sim` に書く道とブラウザが書く道を両方残さない。テストに要るなら起動の設定で閉じた形にする） | ― |
- **本文の固定（M7）**：固定するのは、承認のときに `export_sim` と同じ確かめ（読み直し・承認した行の値・//NAME・`_NAME_OK`・取り消しの印・合成ジョブ・元との違いは2行だけ）を通した**バイト列そのもの**と、その sha256。承認の指紋（`Approval.new_sha256`＝//NAME を変える前のバイト列）とは別に持つ。`/api/save-payload` はその bytes を返すだけで、**作り直さない**（D7）。違う本文を作る道は無い
- **`approval_id`**：推測できない番号（`secrets.token_urlsafe`）。承認ごとに新しくする。payload・check・report はこの番号も一致しなければ断る
- 本文を作るときに、ファイルに書く部分だけを `export_sim` から外す（確かめは同じ関数を通す）
- **保存の名前の検査（M2）**：ブラウザ（書く前）とサーバー（報告の `saved_name`）の両方で、同じ決まりで確かめる：`_SIM.JBI.txt` で終わる（大文字小文字を区別しない）／パスの区切り `\` `/`・`..`・制御文字を含まない／長さの上限（例 120文字）。`.JBI` だけ・`.jbi` だけ・`_SIM.JBI` で終わる名前は書かない
- **サーバーが保証すること／しないこと（S1）**

| 保証する | 保証しない |
|---|---|
| 渡す本文は、承認した差分（承認した行と //NAME の行）だけで、合成ジョブだけ | ファイルが実際に書かれたこと |
| 有効な承認（世代・取り消し・保留・上下の向き・合成ジョブ）にだけ本文を渡す | USB に書き終わったこと（取り外しの前の書き込み） |
| 同じ承認からは同じ本文（バイト列と sha256） | ファイルが、あとで変えられたり名前を変えられたりしないこと |
| 監査の記録（承認・渡した回数・報告・取り消し） | 2つ目のファイルが無いこと（報告が消えたときの再保存） |
- 画面の文は「保存しました（ブラウザの報告）」のまま（D8）

### 3-4. 監査の記録（案B）
- 場所：`records/save_audit.jsonl`（git に入らない。1行1件・追記だけ）
- 1件の中身：`time`（日本時間）・`session`・`candidate_gen`・`approval_id`・`approver`・`job`（元のジョブ名）・`suggested_name`・`saved_name`（ユーザーが付けた名前。パスは入れない）・`sha256`・`payload_count`（その承認で本文を渡した回数）・`event`・`reason`
- `event` の種類：approved／payload／check／report_ok／report_cancel／report_error／refused／**revoked**（承認を取り消した。理由と、その承認で payload を何回渡したか）／**report_after_revoke**（取り消したあとに届いた報告。M5 ③）／**session_closed**（payload を渡したあとに画面が閉じた）／download_handed／report_ok_by_user
- **書き込みは1行ずつ・錠の中で**（同時の報告で行が混ざらない）
- 承認者名・`saved_name` は個人が付けたものなので、`records/`（git に入らない）のまま。リポジトリには入れない
- **保存の報告は「ブラウザがそう言った」ことの記録で、物理的に保存された保証ではない**（D8）。画面の文も「保存しました（ブラウザの報告）」とし、記録の `event` も report_ok と書く
- フォルダのパス（USB の名前など）は記録しない（ブラウザからは取れない。個人の情報を残さない）

### 3-5. 保存できないブラウザ（代わりの方法）
- `showSaveFilePicker` が無いとき：ダウンロード（`<a download>`）で `<ジョブ名>_SIM.JBI.txt` を渡す
- ダウンロードは保存できたかが分からないので、**完了にしない**。画面は「ダウンロードを渡しました。保存されたかは、ブラウザのダウンロードの一覧で確かめてください」。記録は `event: download_handed`
- ユーザーが［保存できました］を押したら、それを「人の申告」として記録する（report_ok_by_user）。物理的な保存の保証ではない。**［保存できました］は承認でも完了でもない**ことを、ボタンの横の文に書く（S2）
- Blob の URL は渡したあとすぐ `revokeObjectURL` する（S2）
- 同じ名前のファイルがあると Chrome は「(1)」を付け、名前が `_SIM.JBI.txt` で終わらなくなる（例 `…_SIM.JBI (1).txt`）。そのことを画面で知らせる（S2）
- このアプリは音声のために Chrome を前提にしているので、ふだんは使われない道
