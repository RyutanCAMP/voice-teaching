## 1. 追加要件と優先順位（共通）

本日中に本番アプリと動画を完成させる。次の2点が**以前からの未反映仕様**と判明したため、本番候補へ優先反映する。

### A. 承認は人間による**明示操作1回だけ**
- 現状の「確認して承認へ」→「承認する」の**二段階の確定操作を1回**にする。単に確認ボタンを無くして安全情報を隠さない。
- 操作者に**対象C番号／対象JOB／軸／符号／移動量／変更前後の数値／3D差分／SIM専用・実機非接続／注意事項**を明示し、それを理解した本人が**最後に1回の明示的な承認操作**を行う。
- 承認前の詳細確認は閲覧・スクロール可能。名前入力の運用が現状必要なら維持するが、**名前の入力や通常の画面遷移を「追加の承認」としない**。承認ボタンは差分の確認できる場所に置く。ブラウザーの自動承認・音声の「はい」・候補表示だけで確定しない。
- **未承認ならSIM出力不可**。否定・訂正・対象切替・再読込・キャンセル・値変更で承認状態は正しく失効する。二重クリック、連打、複数タブ、API直叩き、遅い応答、過去の候補でも誤承認／誤出力なし。
- 安全ガード（1指示20mm上限・累積判定・対象／座標系制約・Python側再検証）は**絶対に緩めない**。1クリック化のために承認を形骸化しない。
- もしUX／安全の両立が既存設計では困難なら、勝手に承認を省略せず**具体的な代案を出して唐川へ判断依頼**。クロの独立レビュー未完了なら「本番確定」とは扱わない。

### B. SIMファイルの名前と保存先
- **既定ファイル名**：`<元JOBの安全化した基底名>_SIM_YYYYMMDD_HHMMSS.JBI.txt`。例：`DEMO_RJ_XYZ_SIM_20261107_121530.JBI.txt`。
- **日時は日本時間（Asia/Tokyo）**の保存時刻を使用。秒精度で重複する場合も上書きしない（例：末尾に`_02`）。Windows禁止文字、予約名、パストラバーサルなどはサニタイズする。元JOBの名前・拡張子とSIM-only表現を明確に区別。
- **保存時に本人が保存場所を選べること**：Chrome系では可能なら**保存ファイルダイアログ（例：File System Access API の `showSaveFilePicker`）**を、直接のユーザー操作で表示し、場所・ファイル名を選んで保存する。ダイアログが使えない環境（非対応・権限拒否・キャンセル・非セキュアコンテキスト等）は、安全な通常ダウンロードへフォールバックし、ブラウザーの「ダウンロードごとに保存先を確認」設定も案内できるようにする。
- **重要**：OSの「フォルダー選択」と「ファイル名を含む保存ダイアログ」は別物。デスクトップブラウザーから任意のOSパスへ無断書き込みはできない。**実現した方式、ブラウザー依存、未対応条件を正確に報告**。既存のサーバー側`output/sim`保存との関係も説明。ユーザーが指定した保存先に保存した**と誤表示しない**。
- 取り消しは失敗扱いではなく安全に中断。既存ファイルを上書きしない。SIM本文と承認済み差分の一致、元JOB不変、合成JOB限定、ロボットへの送信禁止を維持。
- 保存したファイル名・保存完了の通知は、**実際の書き込み成功を確認してから**表示する。ファイルピッカー／ダウンロードの完了保証の違いは区別する。APIキー・機密パスをログやGitHubに載せない。

### 安全上の追加確認
- **XC-20**（自然言語が別の位置を指しているのに選択位置のまま解釈）を優先修正／検証。
- **XC-23**（否定・取り消しの言い換えで未承認候補が残る）について、承認1回化の前後で回帰を追加。UIから起きないケースもAPI直叩き／異常系として検証。
- **XC-21・22**（候補パネルの重なり・空送信表示）はクーちゃん改善K1〜K8の取り込み判断と合わせて検証。
- 本番候補`release/v1.0-rc`はシクロ統合。本番確定と動画用SHAは唐川が承認するまで固定しない。
- 撮影用バックアップ`60f3d24`／8896は絶対に変更しない。

## 4. クーちゃん — UI/UX主担当：承認・保存画面の精査

- 既存K1〜K8改善`ui/kuchan-ux-1107`と新フローが矛盾しないか、**1回で承認するボタン・差分／警告・保存先選択ボタン・日時付きファイル名・キャンセル／失敗通知**をデザイン精査。
- Apple製品のような直感性（**模倣ではなく使いやすさ**）を目指す。「何を承認するのか」「どこに何を保存したのか」が初見で分かる。
- 最小操作数を追求する一方、**重要警告・SIM専用・実機非接続・差分を隠さない**。ワンクリック承認とワンクリック出力を混同しない。承認済みだけが保存可能。

- 3解像度／実際の保存・承認前後の見た目を確認。候補パネルを会話欄へ重ねる判断と、重要ボタンが隠れないかを明記。
