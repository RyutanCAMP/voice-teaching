# プレビュー画面：使い方と現在の範囲

2026-11-02に新規実装した、出力機能を持たない開発段階の画面です。

## 操作

1. `python -m voice_teaching.web` で起動し、127.0.0.1:8765を開く。
2. 公開用ダミーを読み込むか、ローカルのJBIを選ぶ。UTF-8／CP932は利用者が指定する。失敗した場合は前の読込結果と承認候補を破棄する。
3. 位置番号を選び、経路を再生する。再生は移動先の並びを等速補間する説明用表示であり、実機時間・姿勢・待機・ハンド動作を再現しない。
4. 専門家が用意したプレビュー用の枠JSONを読み込む。枠がなければ変更案は作らない。
5. `C00004を右に10ミリ動かして` または `この位置を上に10mm` のように1位置・1方向・1量で入力する。「この位置」は入力開始時の選択位置に固定する。
   音声なら処理方法を選んで「マイクで話す」を押す。録音開始時に選択位置を固定し、古い候補を破棄する。認識文を確認してから解釈ボタンを押す。録音中はジョブ・枠・位置選択・解釈・承認の操作を止める。
6. Claudeの解釈と入力文をプログラムで照合する。対応する文型は限定しており、数量のない指示、複数操作、曖昧な自由文は変更せず聞き直す。Claudeの自由な説明文は画面へ出さない。
7. 比較欄のXYZ・変更行・前後の移動区間を確認する。ボタンで承認すると**メモリー内のプレビュー**だけを更新する。

承認済みJBIの出力ではありません。ファイル出力・USB書出し・Ethernet転送・ロボット起動の経路はありません。

## 枠JSON

デフォルトの枠・仮上限はありません。画面の基準ファイルSHA-256と一致する設定だけを受け付けます。これは正規化ハッシュによる製品版の引継ぎ機能とは別の、ファイル全体の厳密な照合です。

| フィールド | 指定内容 |
|---|---|
| `preview_only` | `true` のみ。実機用として読み込まない |
| `baseline_hash` | 画面に表示した基準ファイルのSHA-256 |
| `right_axis` | 専門家が選ぶ `X`／`Y`。未定なら `null` で左右の指示を拒否 |
| `right_sign` | 専門家が決めた右方向の符号 `1`／`-1`。未定なら枠自体を読み込まない |
| `positions` | 許可する位置番号をキーとするオブジェクト |
| `positions.<位置番号>.<X/Y/Z>` | `min`／`max`：元の位置からの累積下限・上限（mm）、`step`：1回の量（mm） |

基準を含む範囲（min ≤ 0 ≤ max）と正のstepが必要です。テスト中の架空の枠は実機の承認値ではありません。設定値・左右の軸・符号は本人と専門家の判断を待ちます。

## 止める条件

- PULSE、混在・不明な座標ヘッダー、位置の重複、6数値でない位置などはmmの点として描画しない。
- 単純なMOVL以外、PL（PL=0も含む）／CR付き、未知の命令、分岐、未解決の位置参照があるジョブは再生・変更しない。未対応命令を読み飛ばして動いたように見せない。
- 対応するTIMER／DOUTは命令一覧に残すが、時間やI/Oの結果は再現しない。I/O ONを把持成功に変換しない。
- 共用位置、最初・最後の移動先の変更は未確定として拒否。枠で許可された内部の1点だけを扱う。
- 入力とClaudeの対象・方向・量が一致しない、指示量が元の小数桁に収まらない、1回または累積範囲を超える場合は変更しない。
- 同一の入力トークンは成否にかかわらず1回だけ利用。拒否後に量を変えて自動再試行しない。
- 新しい入力・枠読込・JBI読込・取消・失敗で古い候補を破棄。候補IDと版が合わなければ承認しない。
- 音声の途中結果は別欄に表示するだけ。確定結果も勝手にClaudeへ送らない。失敗・取消時には認識文を採用せず、以前の文を再利用しない。遅れて届いた古い録音のイベントを無視する。
- 音声は1回30秒で終了を要求し、開始・終了の応答にも期限を設ける。マイク許可拒否・通信失敗・無音・未対応をそれぞれ表示し、自動録音再開はしない。

## 音声の処理方法と送信先

Web Speech API（SpeechRecognition / webkitSpeechRecognition）を使用。日本語 `ja-JP`、1回ずつの認識。処理方法は未選択から始め、利用者が録音前に選択する。

- ブラウザー標準：音声がブラウザー提供元の外部サービスで処理される場合がある。送信先の選択は本アプリからは制御できない。社内の利用条件を確認して選ぶ。
- 端末内のみ：`processLocally=true` を指定する。非対応・日本語言語パック不足などはエラーとして止め、外部処理には切り替えない。言語パックの自動インストールはしない。

本アプリ側には音声アップロード・音声保存の経路を作っていない。認識文は画面で確認後、解釈ボタンを押したときだけ、位置番号とともにClaudeへ送る。音声認識サービス側の処理・保持はそのサービスの条件に従う。
[APIの対応とサーバー処理](https://developer.mozilla.org/en-US/docs/Web/API/SpeechRecognition)、[端末内処理](https://developer.mozilla.org/en-US/docs/Web/API/SpeechRecognition/processLocally)。

## 残る作業

- HC20の正式型式、関節軸・寸法・原点、TCP／座標設定、開始姿勢と確認データを揃え、本体動作のモデルを検証する。写真だけで計測値を確定しない。
- 利用するPCでブラウザーの音声処理方法・社内の利用条件・マイク許可・日本語精度を確認する。制御と画面は模擬イベントで検証済みだが、実音声は未検証。
- 実際のClaude APIでの疎通と日本語解釈を確認する。現段階はモックによる検証。
- 元のJBI処理の位置ごとの座標形式判定、隣接区間、文字コードの書出し、丸め、実機形式などの確認を完了させる。
- 専門家の実機用の枠、意味付け、基準と履歴の引継ぎ、承認者と日時を含む永続的な記録、新しいジョブ名での承認内容の出力を実装する。

画面・API・モデル接続は共通の `PreviewSession` を呼びます。将来のMCPサーバーは未実装です。承認操作をモデルの道具としては公開していません。
